ArchiveWebShelf — Bug List
=========================

Status labels: [OPEN] needs work; [RESOLVED] is fixed.

Open bugs and resolved fixes are listed here for reference.

1. [OPEN] Viewer Back arrow does not return to the folder
   Status: Unresolved
   Where: Archive Shelf's archive viewer toolbar
   Expected: Clicking “← Back” should close the open archive and show its
   containing folder, the same as “← Back to folder.”
   Actual: The Back arrow still does not return to the folder reliably, even
   though it was changed to call the same folder navigation action.
   Reproduce: Open any WACZ from a folder, then click the viewer's “← Back”
   arrow.

2. [OPEN] Back inside a multi-view WACZ returns to the archive start page
   Status: Known limitation / investigate later
   Where: ReplayWeb.page controls while viewing
   a multi-view WACZ whose views are displayed inside one captured page.
   Expected: Back would return from “Being Human” to the previous song/view.
   Actual: Back returns to the WACZ's start page. The archive indexes one
   captured page (index.html); song views are displayed within that page, so
   they may not have separate archived navigation history entries.
   Reproduce: Open the WACZ, select “Being Human,” then use ReplayWeb.page's
   in-archive Back control.


************* POINT 1 & 2 are dealing with the same Issue********************************************************************************

3. [OPEN] Recorder needs manual interaction to capture dynamic page content
   Status: Next-version improvement; the current recorder captures requests made
   during the active recording session.
   Where: Archive Shelf Recorder on interactive sites such as Ultimate Guitar.
   Expected: Provide a focused, page-scoped way to capture useful on-page
   variants and their assets (such as instrument views, transpose settings,
   chord diagrams, or note samples) without manually exploring every control.
   Keep unrelated links and site-wide crawling out of the capture.
   Actual: Collapsed, interactive, or lazy-loaded content is absent until the
   user opens it, changes a setting, scrolls, or plays it while recording.
   Starting a recording reloads the page, so page state opened beforehand may
   need to be restored during recording. A previous whole-site crawl collected
   too much unrelated content.
   Reproduce: Start a recording on an interactive music tab, leave its
   instrument, transpose, and playback controls untouched, then stop and inspect
   the archive. Those alternate views or samples are missing unless they were
   loaded during the session.
4. [RESOLVED] Recorder upload fails
   Status: Resolved in Recorder 0.17.3; user confirmed the upload works.
   Where: ArchiveWebShelf Recorder browser extension
   Fix: Send the finished WACZ as a Blob body instead of a streamed request.
